# V2 vs V3：Nsight / SASS / L2 容量与带宽瓶颈定位

时间：2026-10-09。硬件：RTX 3060 12GB（Ampere SM86），PyTorch 2.4.0+cu121，Triton-Windows 3.3.1，Windows。

## 核心结论

**最吻合现有证据的解释：V3 Half-Split 减少了 Q/K 的重复加载、Shared Memory 数据重排与同步，
使 L2/cache 可容纳的小至中等工作负载明显加速；当张量工作集跨过 RTX3060 的 2.25 MiB L2 容量并显著增大时，
最低必须搬运的数据量占主导，V3 的少量额外指令节省不再大幅改变总延迟。**

后续 NCU 实测大 GQA 的 DRAM 带宽利用率约为设备持续峰值的 83–85%；详见 [NCU 指标分析](V2_V3_NCU_硬件计数器验证报告.md)。

两者各自对比完全相同的 Grid、Threads 和 BH/Warps，排除了此轮中重新搜索 Warp 参数造成的加速差异。

## 3. nvdisasm：SASS 静态指令差异

| 指令/资源 | Medium V2 | Medium V3 | Large V2 | Large V3 |
|---|---:|---:|---:|---:|
| 总静态指令位置数 | 184 | 112 | 264 | 152 |
| LDG 全局加载 | 14 | 8 | 22 | 8 |
| STG 全局存储 | 4 | 7 | 4 | 7 |
| LDS Shared 加载 | 4 | 0 | 6 | 2 |
| STS Shared 存储 | 10 | 0 | 18 | 2 |
| SHFL 指令 | 0 | 0 | 0 | 0 |
| BAR 同步 | 7 | 0 | 7 | 3 |
| FMUL | 16 | 8 | 32 | 16 |
| FFMA | 8 | 8 | 16 | 16 |

**技术解读：** V3 的数据复用布局不仅减少 LDG 静态指令位置，还让 Medium 的 LDS/STS/BAR 全部消失，
Large 的 Shared 和 Barrier 数目也减少；两种实现均没有静态 SHFL 指令。不能把本次优化误讲成“减少 Shuffle”；
代码与编译产物显示配对数据重复加载、Shared Memory 布局交换与同步、寄存器需求均有所下降。

**反向成本：** Medium 和 Large 的 STG 静态指令从 V2 的 4 变成 V3 的 7，
说明 Half-Split 的输出分成上下半区分别写回，减少输入读取并不代表所有指令都更少。
SASS 位置数不等于动态指令数、L2 hit 次数或真实 DRAM 事务。

## 4. CUDA Driver API：与 L2 容量和理论显存带宽的比较

| CUDA 属性 | 值 |
|---|---:|
| SM 数 | 28 |
| L2 Cache | 2359296 bytes = 2.25 MiB |
| Memory Clock | 7501000 kHz |
| Memory Bus Width | 192 bit |
| 理论峰值 DRAM 带宽（双倍数据率推算） | 360.05 GB/s |

在本项目的四份输出中，理论上至少会触及以下独立数据：

- Q 原始数据 1 份 + Qrot 输出 1 份。
- K 输入 1 份 + Krot 输出 1 份 + Kcache 写入 1 份。
- V 输入 1 份 + Vcache 写入 1 份。

设每个 FP16 Q Tensor 的大小为 Q_bytes，每个 K/V Tensor 的大小为 KV_bytes，
则 **最低逻辑输入/输出字节量 = 2·Q_bytes + 5·KV_bytes**。未计算 Cos/Sin、slot 以及 Cache Line 放大。

| 形状 | 最低逻辑 I/O | 额外只计算一次的 Cos/Sin | 相对 2.25MiB L2 |
|---|---:|---:|---|
| medium | 1.625 MiB | 0.0312 MiB | 低于 L2 |
| large | 10.5 MiB | 0.1250 MiB | 显著高于 L2 |

Large V3 的最低逻辑吞吐量 = 11010048 Bytes / 35.680 μs ≈ **308.6 GB/s**，约为峰值 360.1 GB/s 的 **85.7%**。
这里特意称为“最低逻辑 I/O 的有效吞吐量”，**不声称它是测得的 DRAM 带宽**；
一些输入读写会由 L1/L2 缓存承载，DRAM 事务也可能存在额外粒度/重放开销。

### 为什么这组扫描很重要？

- 固定 Hq32/Hkv8，最低逻辑 I/O 加上每 Token 一套 Cos/Sin 约 27136 bytes/Token； 2.25 MiB 可容纳的理论量约 86.9 Tokens。实测 T80 较快、T88–96 开始明显转折。
- 固定 Hq64/Hkv8，每 Token 约 43520 bytes；理论 L2 容量交界约 54.2 Tokens，实测 T48 仍有明显 Half-Split 收益，到 T64–96 显著下降。
- 大型工作负载进入稳态后，最低逻辑吞吐普遍在约 290–306 GB/s，接近设备理论带宽的多数比例。

这是**跨两个独立 Head 配置、只改变 T，且在 L2 容量附近发生转折**的证据链。与数据搬运压力增大的解释相符。
不过：L2 的容量只是重要线索，缓存替换策略、Q/K Cache 随机槽位写入、线程布局以及时钟变化也会影响转折。
后续已采集 L2/DRAM 计数器，见 [NCU 专项报告](V2_V3_NCU_硬件计数器验证报告.md)。

## 6. 综合分析

固定 BH4/W4 的中 GQA 中，V3 的 Nsight Systems Kernel 时间由 3.936 μs 降至 2.752 μs。SASS 中 LDG 静态指令位置减少、LDS/STS/BAR 位置消失；后续 NCU 显示动态执行指令下降约 47.5%，Shared Bank Conflict 从 10,407 降至零，但 DRAM 总读写量并未下降。

固定 BH2/W1 的大 GQA 中，V2 和 V3 Kernel 时间分别为 35.825/35.680 μs。NCU 的 DRAM 读写量基本持平，带宽利用率约为持续峰值的 83–85%。工作集增加后，片上指令优化的收益受到外部数据搬运约束。
