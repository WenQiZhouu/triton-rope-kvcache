# V2 Head Tiling 实验报告：BH=2/4/8 × Warps=1/2/4

日期：2026-10-08；GPU：NVIDIA RTX 3060 12GB；Windows，PyTorch 2.4.0+cu121，Triton-Windows 3.3.1。

## 实验范围与公平性

- 参数 BT=1、BD=128 保持不变；BH=1/2/4/8 与 num_warps=1/2/4 完整网格搜索，三个 GQA 形状每个 12 种配置。
- BH=1 使用**原有的 matched_kernels.py**，没有通过重写基线获得加速；BH=2/4/8 在新增的 head_tiling.py 中以 [BH,128] Triton 二维逻辑 Tile 执行 Q/K RoPE + K/V Cache Write。
- 为统一输出，所有版本写 Q_rot、K_rot、Paged K/V Cache。NeoX 全维 RoPE，FP16 性能；按前期 SGLang 官方单 Kernel 匹配输出协议。
- 采用 CUDA Graph replay（triton.testing.do_bench_cudagraph），预分配张量，每个配置每轮约 25ms 计时，**5 次交错重复取中位数**，并做两轮独立完整实验。
- 每一种配置在计时之前用 PyTorch 参考独立检验 Qout/Kout/Kcache/Vcache。额外边界检测 FP16/FP32、无效 slot、Hq 不整除 BH 和 D=96。
- 运行顺序旋转、偶数轮逆序，以减少 GPU 频率随时间变化的顺序偏差。
- 所有报告中的加速比来自每轮**同样设备、相同输入、同一程序运行中重新测量的 BH=1**；不与历史 CSV 的微秒绝对时间混算。

## 程序数量和资源占用

程序数量：T × ceil(QH/BH)。以 T=64,QH=32 为例：BH=1→2048, BH=2→1024, BH=4→512, BH=8→256。

下面是 Triton 3.3.1 在这次 FP16 配置下生成的内核编译元数据（BH>1 与 Shape 无关的主要数据）：

| BH | Warps | Registers / Thread | Shared Bytes / CTA |
|---:|---:|---:|---:|
| 2 | 1 | 56 | 544 |
| 2 | 2 | 42 | 528 |
| 2 | 4 | 29 | 520 |
| 4 | 1 | 82 | 1088 |
| 4 | 2 | 55 | 1088 |
| 4 | 4 | 40 | 1056 |
| 8 | 1 | 128 | 2176 |
| 8 | 2 | 64 | 2176 |
| 8 | 4 | 48 | 2176 |

解释：当 BH 增大时，虽然逻辑上可复用 Cos/Sin 且可减少 Program 数量，但寄存器和 Shared Memory 分配上升。
BH=8/W1 使用 128 个寄存器/线程 + 2176B/CTA Shared；过大 Tile 可能降低驻留 CTA 数，Program 数减少并不保证内核速度提高。BH>1 使用的 Shared Memory 也表明“跨 Head 广播完全免费”并不成立，需要结合生成的布局/代码解释。

### 输入规模与并行度

- 小 Decode：T=1、QH=32，BH=1 有 32 个 Program，BH=8 只有 4 个 Program，难以铺开 GPU 多个 SM；**BH=1 是两轮最优**。
- 中 GQA：T=64 有足够多的 CTA，BH=4 削减过细 Program，同时增加每 Program 有效工作与 Cos/Sin 逻辑复用；**BH=4/W4 两轮最快**。
- 大 GQA：T=256 时 BH=1 已有 16384 个 Program；BH=2/4 可显著减少任务数量，但整个工作负载的缓存写与数据量没有变化，因此消除 Warp 配置差异后的 Head Tiling 增量收益只约 3%；继续增大到 BH=8 不再有持续优势。

初始 Head Tiling 扫描主要分析 Kernel 时间和编译资源，后续选定配置补充了 Nsight Compute 计数器，DRAM、Occupancy 和 Stall 结果见 [NCU 分析](V2_V3_NCU_硬件计数器验证报告.md)。

## 限制

- 仅对三组 GQA FP16 Shape 性能调优，不能直接外推到 MHA、MQA、FP32 或其他 Head Dim。
- 第一轮和第二轮中等规模的绝对时间和官方单 Kernel 参照数值有波动，因此**应同时报告两轮复测区间，而非单次最低耗时**。
- 由于只试了离散 BH=1/2/4/8 与 Warp=1/2/4，选择最优会有测量与搜索偏差；没有证明 BH=4 是全局最优。
- 未集成到实际推理框架，也未测多模型并发。
