# V3 Half-Split RoPE 实验报告

环境：2026-10-09，RTX 3060 12GB，PyTorch 2.4.0+cu121，Triton-Windows 3.3.1。

## 设计与公平对照

- V2：每个 RoPE 输出元素加载自身与配对特征，逻辑 GM 元素加载量为 2D。
- V3：每个逻辑线程元素同时持有 x[i] 和 x[i+D/2]，计算两个输出，逻辑 GM 元素加载量为 D。通过同一逻辑元素内寄存器复用，避免显式 reshape/flip。
- V Cache 路径保持 V2 的单块读取；固定 (T,Hq,Hkv,D,BH,Warps)，成对运行两个版本，预分配输出，CUDA Graph 回放，5 轮交错取中位数。
- V2 中 BH=1 使用原 matched_kernels.py；BH>1 使用原 head_tiling.py，全部不修改。
- Qrot/Krot/Kcache/Vcache 均与 PyTorch 独立参考核对。边界测试包括 FP16/FP32、D64/D96/D128、无效 Slot、Head 非整除。
- 本实验限于 FP16、D128、全维 NeoX RoPE、Flash Cache Layout 和 RTX 3060，不代表通用推理端到端吞吐。

## 两轮同配置对照

| 规模 | BH/Warps | 第一轮 V2→V3 (μs) | 加速 | 第二轮 V2→V3 (μs) | 加速 |
|---|---|---|---:|---|---:|
| 小规模 GQA | 1/4 | 1.7146→1.64 | 1.0455× | 1.7659→1.689 | 1.0455× |
| 中规模 GQA | 4/4 | 4.6594→3.2831 | 1.4192× | 4.7509→3.1984 | 1.4854× |
| 大规模 GQA | 2/1 | 36.4193→36.2638 | 1.0043× | 36.6064→36.396 | 1.0058× |

**判断**：小规模约 3–5% 提升；中等 GQA BH4/W4 两轮都约 1.42–1.49× 加速；大 GQA 仅约 0.5–1%，在波动水平附近，不能宣称明确的实质性收益。
